    ${CMAKE_CURRENT_SOURCE_DIR}/src/utils.cpp
)
set(TARGET_DIR ${CMAKE_CURRENT_BINARY_DIR}/Source_Files)

# 2. Create the physical directory on your disk
file(MAKE_DIRECTORY ${TARGET_DIR})

# 3. Copy the files into the new physical folder
foreach(FILE_PATH ${SOURCES})

endforeach()



Why you shouldn't rely on the "Add Item" UI anywayIn CMake-based workflows, the CMakeLists.txt is the single source of truth.

If you use Visual Studio's "Add New Item" UI, it physically places the file on disk but does not automatically update your add_executable 
or add_library calls in CMakeLists.txt cmake.org.The next time CMake runs or configures, 
your new file might be ignored or dropped from the build compilation until you manually type it into your CMake script.
Best Practice: Create the file directly in your source folder using Windows Explorer or an editor, 
then type the filename directly into your CMakeLists.txt.



To add items or source files to a CMake-based project in Visual Studio, you must update your CMakeLists.txt file 
rather than relying on Visual Studio's traditional solution explorer UI.Best Practices for Adding ItemsUpdate CMakeLists.txt directly: 
Create your new .cpp or .h files on disk in your project folder, then add them explicitly to the relevant target using target_sources 
or add_executable/add_library. 

Use target_* commands: Avoid global commands like add_definitions or pulling all files via giant wildcard variables; 
instead, scope sources and properties directly to specific targets using modern CMake patterns.

Organize with Source Groups: Use source_group commands in your CMakeLists.txt 
if you want custom virtual folder layouts inside Visual Studio's Solution Explorer that match your disk structure. 

Trigger a re-configure: After editing CMakeLists.txt, Visual Studio automatically detects the change and updates the CMake cache, 
but you can manually right-click CMakeLists.txt and select Re-configure if it fails to sync.
